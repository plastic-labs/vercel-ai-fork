# Honcho

`@honcho-ai/ai-sdk` is an reasoning-native memory fabric for AI SDK apps. [Honcho](https://honcho.dev) goes beyond traditional RAG retrieval by deriving conclusions, maintaining an evolving user representation, and reinjecting the right context at generation time.

Out of the box, Honcho delivers a state-of-the-art memory loop: persist -> reason -> reinject.

The redesigned API is flat and low-ceremony by design:

- `createHoncho()`
- `honcho.middleware({ userId?, sessionId?, assistantId?, ... })`
- `honcho.tools({ userId?, sessionId?, assistantId? })`
- `honcho.send({ userId?, sessionId?, content })`

<Note>
  Honcho is not a model provider. Use it alongside `@ai-sdk/openai`,
  `@ai-sdk/anthropic`, or any other AI SDK model provider.
</Note>

### Environment Variables

Set your Honcho API key and workspace ID:

```bash
export HONCHO_API_KEY=your-api-key
export HONCHO_WORKSPACE_ID=your-workspace-id
```

By default, `createHoncho()` reads workspace from option or env var.  
If both are missing, it implicitly falls back to workspace `"vercel-ai-sdk"` (with a one-time warning).

## Quick Start

```typescript
import { createHoncho } from '@honcho-ai/ai-sdk';
import { generateText } from 'ai';
import { openai } from '@ai-sdk/openai';

const honcho = createHoncho();

const { text } = await generateText({
  model: openai('gpt-4o-mini'),
  middleware: honcho.middleware(),
  prompt: 'What should I focus on this week?',
});
```

This injects Honcho context using lazily generated peer/session IDs.
For deterministic identity/threading, pass explicit IDs or provider defaults.

## Plug-and-Play Defaults

Workspace fallback is implicit. If `workspaceId` and `HONCHO_WORKSPACE_ID` are both missing,
Honcho uses workspace `"vercel-ai-sdk"` (with a one-time warning).

Plug-and-play works with no explicit IDs. If `userId` or `sessionId` is omitted,
the provider lazily generates stable IDs for that provider instance:

```typescript
const { text } = await generateText({
  model: openai('gpt-4o-mini'),
  middleware: honcho.middleware(),
  tools: honcho.tools(),
  maxSteps: 3,
  prompt: 'What should I focus on today?',
});
```

You can still set explicit provider defaults for deterministic IDs:

```typescript
const honcho = createHoncho({
  defaultUserId: 'user',
  defaultAssistantId: 'assistant',
  defaultSessionId: 'session',
});
```

Resolution behavior:

- `assistantId` defaults to `"assistant"`
- missing `userId` lazily generates a provider-scoped user ID
- missing `sessionId` lazily generates a provider-scoped session ID

To disable session behavior for a specific call, pass `sessionId: null`.

## Add Persistence

Set `sessionId` when you want to control explicit thread boundaries.
Session mode is active by default (auto-generated when omitted), and can be
disabled per call with `sessionId: null`.

```typescript
const { text } = await generateText({
  model: openai('gpt-4o-mini'),
  middleware: honcho.middleware({
    userId: 'user-123',
    sessionId: 'chat-456',
  }),
  prompt: 'What should I focus on this week?',
});
```

When session mode is active:

- model output is always persisted as the assistant peer
- user input is persisted when `persistInput` is `true` (default)

## Middleware Behavior

Honcho middleware handles two phases automatically:

1. **Before generation (`transformParams`)**

   - lazily ensures peers/session
   - fetches context (representation, card, summary, and optional history)
   - injects context into system prompt

2. **After generation (`wrapGenerate` / `wrapStream`)**
   - persists assistant output
   - persists user input when enabled
   - avoids re-persisting user input during tool continuation steps

### Messages Array + No Duplication

If you pass `messages` directly to `generateText`, disable injected history:

```typescript
const result = await generateText({
  model: openai('gpt-4o-mini'),
  middleware: honcho.middleware({
    userId: 'user-123',
    sessionId: 'chat-456',
    injectHistory: false,
  }),
  messages,
});
```

## Tools

Honcho exposes six tools for in-loop memory reasoning and retrieval:

| Tool                        | Description                                                                         |
| --------------------------- | ----------------------------------------------------------------------------------- |
| `honcho_chat`               | Ask Honcho's dialectic reasoning engine a natural-language question about the user. |
| `honcho_context`            | Retrieve context (representation, card, summary, recent messages).                  |
| `honcho_search`             | Semantic search over stored conversation messages.                                  |
| `honcho_search_conclusions` | Query derived conclusions (traits, preferences, behavioral patterns, facts).        |
| `honcho_get_representation` | Get a synthesized representation of what Honcho knows.                              |
| `honcho_save_conclusion`    | Save an observation/conclusion for future use.                                      |

```typescript
const { text } = await generateText({
  model: openai('gpt-4o-mini'),
  middleware: honcho.middleware({
    userId: 'user-123',
    sessionId: 'chat-456',
  }),
  tools: honcho.tools({
    userId: 'user-123',
    sessionId: 'chat-456',
  }),
  maxSteps: 3,
  prompt: 'What patterns have you noticed about me?',
});
```

## Multi-Peer Conversations

Use `assistantId` to choose which agent identity is generating:

```typescript
await generateText({
  model: openai('gpt-4o-mini'),
  middleware: honcho.middleware({
    assistantId: 'agent-coordinator',
    userId: 'alice',
    sessionId: 'group-123',
  }),
  prompt: 'Coordinate next steps for Alice.',
});
```

```typescript
await generateText({
  model: openai('gpt-4o-mini'),
  middleware: honcho.middleware({
    assistantId: 'agent-specialist',
    userId: 'bob',
    sessionId: 'group-123',
  }),
  prompt: 'Respond as specialist for Bob.',
});
```

## Manual Input Persistence (`honcho.send`)

When your app persists user input itself, call `send()` and disable `persistInput` in middleware:

```typescript
await honcho.send({
  userId: 'alice',
  sessionId: 'group-123',
  content: 'Can you help me plan this sprint?',
});

const { text } = await generateText({
  model: openai('gpt-4o-mini'),
  middleware: honcho.middleware({
    assistantId: 'coordinator',
    userId: 'alice',
    sessionId: 'group-123',
    persistInput: false,
  }),
  prompt: 'Can you help me plan this sprint?',
});
```

## Next.js Route Handler Example

```typescript
import { createHoncho } from '@honcho-ai/ai-sdk';
import { streamText, convertToModelMessages } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';

const honcho = createHoncho({
  defaultAssistantId: 'my-app',
});

export async function POST(req: Request) {
  const { messages, sessionId, userId } = await req.json();

  const result = streamText({
    model: anthropic('claude-sonnet-4-6'),
    middleware: honcho.middleware({
      userId,
      sessionId,
      injectHistory: false, // messages already contain history
    }),
    tools: honcho.tools({ userId, sessionId }),
    messages: await convertToModelMessages(messages),
  });

  return result.toUIMessageStreamResponse();
}
```

## Configuration Reference

### `createHoncho(options?)`

```typescript
const honcho = createHoncho({
  // auth/workspace
  apiKey: process.env.HONCHO_API_KEY,
  workspaceId: process.env.HONCHO_WORKSPACE_ID,

  // provider-level defaults (optional)
  defaultUserId: 'user',
  defaultAssistantId: 'assistant',
  defaultSessionId: 'session',

  // networking (optional)
  environment: 'production', // or 'local'
  baseURL: 'https://api.honcho.dev',
  timeout: 30_000,
  maxRetries: 2,
  defaultHeaders: {
    'x-app': 'my-app',
  },
});
```

### `honcho.middleware(config?)`

```typescript
{
  userId?: string;
  sessionId?: string | null;
  assistantId?: string;      // default: "assistant"
  persistInput?: boolean;    // default: true
  injectHistory?: boolean;   // default: true
  formatContext?: (context) => string;
  onError?: (error) => void;
}
```

### `honcho.tools(config?)`

```typescript
{
  userId?: string;
  sessionId?: string | null;
  assistantId?: string;      // default: "assistant"
}
```

## Additional Modules

| OpenAI   | `@honcho-ai/ai-sdk/openai`   | Direct OpenAI SDK integration (without AI SDK tool wrappers). |

<Note>
  The redesigned API no longer exposes `@honcho-ai/ai-sdk/multi-agent` as a
  separate entry point. Multi-peer scenarios are handled by varying
  `assistantId` per call.
</Note>

### OpenAI (`@honcho-ai/ai-sdk/openai`)

```typescript
import OpenAI from 'openai';
import { createHoncho } from '@honcho-ai/ai-sdk';
import { honchoOpenAITools } from '@honcho-ai/ai-sdk/openai';

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });
const honcho = createHoncho();

const honchoTools = honchoOpenAITools({
  client: honcho.client,
  defaultPeerId: 'user-abc',
  defaultObserverPeerId: 'assistant-xyz',
  defaultSessionId: 'session-123',
});
```

Pass `honchoTools.definitions` to OpenAI tool calling, then execute each call with `honchoTools.execute(name, args)`.
